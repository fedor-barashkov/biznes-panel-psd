# Реестр архитектурных решений и открытых вопросов

**Версия:** 0.1  
**Дата:** 2026-11-08  
**Назначение:** единый журнал решений для проектирования экосистемы ИТД и строительных ИИ-агентов.

## 1. Правила статусов

- **Утверждено** — пользователь прямо подтвердил решение.
- **Ранее утверждено** — решение было подтверждено в предыдущих обсуждениях и перенесено в текущую консолидацию.
- **Предложение** — рабочая рекомендация, требующая подтверждения.
- **Требует проверки** — необходим исходный файл, нормативный источник, технический аудит или испытание.
- **Открыто** — решение ещё не принято.

Если обнаружено противоречие, приоритет имеет более позднее прямое решение пользователя. Не менять утверждённые решения молча.

## 8. Правила работы с открытыми вопросами

- Не задавать пользователю весь список вопросов одновременно.
- Сначала самостоятельно исследовать доступные репозитории, файлы и нормативные источники.
- Задавать один наиболее важный вопрос только тогда, когда без решения нельзя продолжать.
- Не просить повторно файл, пока не проверены доступные вложения и библиотека.
- Не считать отсутствие найденного файла доказательством, что он потерян.
- Не превращать предложенный вариант в утверждённое решение.
- При изменении решения указывать, какой пункт и почему заменён.

## 11. Уточнение ранее выглядевших противоречивыми правил передачи

В более раннем ТЗ одновременно использовались формулировки «поэтапная передача» и «частичная приёмка». Позднее пользователь уточнил принцип комплектности. Для реализации применяется следующее совместное прочтение:

1. Пользователь выбирает область передачи: объект, подобъект или явно определённую группу/этап.
2. В пределах выбранной области формируется полный комплект ИД по установленным правилам комплектности.
3. Допускается несколько отдельных полных комплектов для разных подобъектов/этапов и последующий общий комплект.
4. После передачи заказчик может принять не все документы сразу; приёмка каждого документа отражается отдельно.
5. Предыдущий снимок передачи не меняется; исправленная повторная передача формирует новый снимок.

Таким образом, **частичная приёмка документов допускается, частичная отправка произвольной выборки вместо полного комплекта выбранной области — нет**.

## 12. Особое внимание перед реализацией

| Риск | Контрольное правило |
|---|---|
| Смешение статусов | Статус приёмки отделять от подготовки, согласования, замечаний, передачи и регистрации |
| Печатный реестр | Не выводить внутренние статусы; сверять по эталону |
| Подмена источников | Все распознанные/вычисленные значения имеют provenance и подтверждение |
| Принятые документы | Не менять принятый экземпляр; только отдельная контролируемая процедура |
| Передачи | Полный комплект в пределах выбранной области; частичная приёмка — на уровне отдельных документов |
| Избыточный интерфейс | Контекстная лента, простые сценарии, детали по запросу |
| Зависимость агентов | Отдельный репозиторий, контракт и адаптеры; не привязывать к ИТД или одной модели |
| Расширение объёма | Не задерживать основной релиз ИТД сметами, финансами и общей аналитикой |
| Нормативная актуальность | Проверять официальный источник и редакцию на дату реализации; не считать историческую запись нормативным доказательством |
