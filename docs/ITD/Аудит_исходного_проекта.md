## 2. Текущий технологический профиль

- HTML, CSS и JavaScript находятся в одном `index.html`; отдельные исходные модули и система сборки в проверенном составе не обнаружены.
- Стили интерфейса встроены в документ; используется визуальная система с адаптацией под светлую/тёмную тему.
- Внешняя зависимость интерфейса, явно обнаруженная в HTML, — Lucide UMD с CDN `unpkg.com`.
- Внешние ES-модули и импорты в проверенном файле не обнаружены.
- Отдельная сборка Windows EXE/установщика в README и составе исходников не описана.

## 3. Хранение данных и режимы запуска

- В автономном режиме данные хранятся в `localStorage` браузера под ключом `psd-items`.
- При наличии среды Claude приложение использует `window.claude.use('db')` для общей базы и `window.claude.use('sample')` / `window.claude.use('downloads')` для дополнительных возможностей.
- Резервная копия реализована как JSON-экспорт/импорт записей панели.
- По проверенному коду не обнаружено использования IndexedDB, SQLite или отдельного серверного API приложения.
- README прямо указывает, что при локальном запуске данные принадлежат конкретному браузеру/компьютеру; очистка браузерных данных может привести к их потере без резервной копии.

## 4. Существующие функциональные заделы

В коде присутствуют формы и функции, относящиеся к объектам, ИТД, актам, АОСР, журналам, реестру ИД, печати, импорту/экспорту резервной копии и поиску. Найдены, в частности, функции `docAOSR`, `docJournal`, `docRegistry`, `openPrint`, `exportData` и `importData`.

Наличие этих функций не подтверждает соответствие действующим требованиям первой версии. Каждая форма должна быть сопоставлена с актуальным ТЗ, пользовательскими шаблонами, структурой данных и критериями приёмки.

## 5. Предварительные выводы и риски

1. Текущий код — браузерная монолитная панель, а не готовое настольное Windows-приложение.
2. Хранение в `localStorage` не обеспечивает требуемую полноценную транзакционную БД, надёжное файловое хранилище, историю редакций и сетевую синхронизацию.
3. Зависимость от API среды Claude не может быть обязательной для самостоятельного EXE.
4. Внешняя загрузка иконок с CDN должна быть заменена локальным ресурсом или иным автономным механизмом.
5. Нужно отдельно проверить фактическую структуру и качество существующих форм АОСР, журналов, реестров и печатных представлений.
6. До анализа Excel-автоматизатора нельзя окончательно определить, какие механизмы и справочники целесообразно переносить, а какие следует реализовать заново.
7. До динамического запуска нельзя утверждать, что текущая панель полностью работоспособна, безопасна или не содержит ошибок.

### 9.1. Подтверждённые факты

- Приложение — единый HTML-документ со встроенными CSS и JavaScript; в проверенном файле нет разбиения на исходные модули.
- Визуально реализована старая панель с тремя зонами: «Сметы», «ИТД», «Бизнес». Это не соответствует целевой самостоятельной программе ИТД с главной навигацией «Объекты» / «База».
- В исходнике определены типы записей и формы через общую структуру JavaScript, функции рендеринга и шаблоны HTML-строк.
- Локальное хранилище — `localStorage`, ключ `psd-items`; настройки зоны и темы также хранятся в `localStorage`.
- При запуске внутри Claude используются `window.claude.use('db')`, `sample` и `downloads`. Это API среды Claude, а не универсальный интерфейс приложения.
- В автономном режиме предусмотрены JSON-резервная копия и импорт записей. Это не полноценное резервирование БД, файлов, версий и связей.
- В проверенном HTML нет использования IndexedDB, SQLite, собственного HTTP API, `fetch()`, XMLHttpRequest или загрузчика PDF/Excel. Отсутствие этих механизмов установлено только для проверенного файла.
- Иконки загружаются внешним скриптом Lucide с CDN `unpkg.com`; это препятствует гарантированной автономной работе без сети.
- В коде есть функции печати АОСР, журналов и реестра. Реестр в текущей реализации строится из записей типа `idact`; в печатную таблицу выводится колонка «Статус». Это противоречит утверждённому требованию о печатной форме реестра без внутренних статусов и с точным соответствием эталону.
- Функция печати АОСР использует набор значений из старой карточки объекта и записи акта. Это не заменяет полноценную структурированную модель полей, редакций, происхождения значений и пользовательский эталонный шаблон.
- Статусы записей старого типа `idact` включают «Черновик», «На подписи», «Замечания», «Подписан». Это не целевая модель приёмки «Принят» / «Не принят»; статусы рабочего процесса должны храниться отдельно от статуса приёмки.
- Текущая функция сохранения в общей базе Claude сначала меняет локальное состояние интерфейса, затем выполняет асинхронную запись. При ошибке записи состояние интерфейса может временно расходиться с серверным. Аналогично удаление из локального состояния происходит до подтверждения серверного удаления. Это статически выявленный риск, который требуется проверить и устранить в новой архитектуре.
- Функция нормализации `SAFE` ограничивает длину строк и число элементов массивов/объектов. Перед переносом данных требуется проверить, не приводит ли это к усечению длинных описаний, текстов и структурированных записей.
- По текущему коду нельзя подтвердить наличие полноценной модели редакций, неизменяемых оригиналов, provenance, подтверждения приёмки, неизменяемых снимков передач, транзакционной синхронизации и восстановления связанного набора данных.

### 9.3. Предварительное решение по повторному использованию

Старый `index.html` сохраняется как функциональный и UX-референс. Из него можно повторно использовать после проверки отдельные формулировки, структуру справочников, последовательность пользовательских действий, полезные поля и отдельные идеи визуального представления.

Не переносить монолитный HTML как основу целевой архитектуры без отдельного обоснования. Не переносить напрямую схему хранения `localStorage`, зависимость от Claude API, печатные шаблоны и статусы старой панели. Эти части не удовлетворяют целевым требованиям.

Это не решение о полном переписывании без аудита: каждый полезный блок должен быть сопоставлен с ТЗ и классифицирован как «сохранить», «адаптировать», «заменить» или «исключить».

### 9.4. Что ещё не проверено

- Динамический запуск старой панели и тестирование всех пользовательских сценариев.
- Проверка безопасности обработки недоверенного содержимого и HTML-экранирования во всех формах.
- Полный анализ всех полей, типов записей и взаимосвязей старой панели.
- Сравнение старых печатных форм с нормативными формами и пользовательскими эталонами.
- Содержимое архива `agenerator_5.26.10.09_.zip`, книги `Автогенератор 5.26.10.09.xlsm`, VBA и Power Query.
- Проверка сборки и запуска на Windows, поскольку сборочная конфигурация отсутствует.
- Совместимость с сетевым режимом и многопользовательской работой.
