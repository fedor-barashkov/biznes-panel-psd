# История изменений проектной документации ИТД

## 2026-11-03 — базовый регламент разработки
- Утверждён многоагентный регламент ChatGPT/Codex v1.1.
- Зафиксированы роли ANALYST/ARCHITECT, IMPLEMENTER и QA.
- Установлено правило не переписывать существующий GitHub-проект без аудита и обоснования.
- Целевой результат — готовые Windows EXE.

## 2026-11-04 — начало проектирования ИТД
- Прежнюю бизнес-панель решено разделить на три независимые программы: ИТД, сметы, бизнес.
- Первым приоритетом стало самостоятельное приложение ИТД.
- Исходные материалы: GitHub-репозиторий и Excel-автоматизатор.
- Шаблон АОСР пользователя определён как эталон содержания и структуры.
- Зафиксированы требования к объектам/подобъектам, организациям/СРО, представителям, OCR/импорту, актам, материалам, схемам, протоколам, ПД/РД и журналам.

## 2026-11-04 — реестры и передача заказчику
- Подтверждён макет 0.8 — реестр ПД/РД.
- Подтверждён макет 0.9.9 — реестр ИД и комплекты передачи.
- Установлены правила частичной приёмки, блокировки принятых документов, повторной передачи, снимков комплектов и входящих документов заказчика.

## 2026-11-05 — главный экран, ВОР и системные контуры
- Согласованы блоки главного экрана и панели инженера ПТО.
- Подтверждены глобальный поиск, единый центр импорта и единая карточка объекта.
- ВОР определена как самостоятельный раздел, не обязательный для начала ИТД.
- Подтверждён макет 1.0.9 по сопоставлению ВОР, КС-2, КС-6а и ИТД.
- Выбрана гибкая модель прав: базовая роль плюс индивидуальные разрешения.
- Выбран комбинированный режим локальной/сетевой работы; места размещения — офисный сервер, NAS, удалённый сервер.
- Приняты ключевые правила резервирования в нескольких местах, защиты документов, корзины/архива и аудита.
- Подтверждены категории уведомлений, эскалация и пять каналов первой версии.
- Для аналитики выбрана комбинированная панель: сводка и карточки объектов.
- Для управленческой аналитики выбрана модель доступа по иерархии с индивидуальными разрешениями.
- Для сроков выбраны комбинированные источники производительности: нормативный, фактический и ручной.
- Технологическая последовательность, порядок и даты задаются пользователем вручную.
- Общее прогнозирование рисков/срыва сроков исключено; оставлен расчёт продолжительности работ по объёмам и производительности.

## 2026-11-05 — макет 1.0.16: типы документов и шаблоны
- Согласован гибридный механизм: стандартные типы поставляются с приложением; пользовательские типы создаются через конструктор; типы импортируются из других объектов/проектов.
- Обычное добавление новых типов актов и журналов не должно требовать изменения программного кода.
- Утверждено разграничение полномочий по шаблонам: просмотр, создание типа, загрузка, редактирование черновика, согласование, публикация, архивирование и восстановление регулируются раздельными правами.
- Создание и публикация шаблона разделены; официальный выпуск по шаблону разрешён только после публикации.
- Выпущенный документ сохраняет редакцию шаблона, на основе которой создан.
- Утверждён жизненный цикл шаблона: черновик → на проверке → согласован → опубликован → заменён новой редакцией или архивирован.
- Замечания возвращают шаблон на доработку с сохранением истории; каждая редакция проверяется отдельно.
- Опубликованную редакцию нельзя редактировать напрямую; публикацию можно отозвать при ошибке без изменения ранее выпущенных документов.
- Восстановление предыдущей редакции требует фиксации причины; нормативные изменения требуют проверки шаблона, но не меняют его автоматически.
- Все действия с шаблонами журналируются.
- Макет 1.0.16 продолжает проектироваться; утверждены только перечисленные решения.
